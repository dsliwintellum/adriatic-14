# Adriatic 14

A mobile-first, installable 14-day conversational language coach tailored to a Croatia–Montenegro trip through Dubrovnik Airport, Perast, Žabljak, Korčula, and Dubrovnik.

## What is included

- 14 route-based missions
- 143 searchable Croatian, Montenegrin, and shared phrases
- Automatic Croatia/Montenegro vocabulary mode switching
- Device text-to-speech playback with explicit Croatian/Serbian-compatible voice selection
- Speech-recognition practice where the browser supports it
- Meaning quizzes, flashcards, listening checks, and branching role-play
- A large “Say it now” offline phrase card
- Saved progress, favorites, phrase comfort ratings, and JSON export
- Responsive desktop and mobile layouts
- Web app manifest, icons, and service-worker caching for PWA installation/offline use
- No build step, package manager, backend, account, or API key

## Run locally

The app is static, but PWA installation and service-worker caching require HTTP rather than opening `index.html` directly.

```bash
cd adriatic14
python3 -m http.server 8080
```

Open `http://localhost:8080` in a browser.

For a quick non-PWA preview, open `adriatic14-preview.html` directly. The one-file preview includes the complete course but intentionally omits service-worker installation.

## Publish with GitHub Pages

1. Put the deployable files in the root of a GitHub repository.
2. In the repository, open **Settings → Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**.
4. Select the publishing branch and `/(root)`, then save.

No build action is required. The app uses hash-based routes, so all screens work from the single `index.html` entry point.

GitHub’s current publishing-source documentation:  
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Install on a phone

After the app is published over HTTPS, open it in a supporting mobile browser and use the browser’s install or **Add to Home Screen** command. Installation UI varies by browser and operating system.

The PWA requires an HTTPS host (GitHub Pages qualifies) or a localhost development URL. Opening the files with a `file://` URL does not provide the installable/offline PWA behavior.

## Edit the curriculum

All language content is in `content.js`.

- Add or edit an object in the `phrases` array.
- Reference phrase IDs from a lesson’s `phraseIds` array.
- Each lesson contains its own dialogue, three-question quiz, and branching scenario.
- Use `country: 'croatia'`, `country: 'montenegro'`, or `country: 'shared'`.

The UI and lesson engine do not need to change when content is added.

## Browser behavior

Text-to-speech and speech recognition use the browser’s Web Speech APIs. Playback now waits for the browser voice list and requires a Croatian or Serbian-compatible voice; it will not silently fall back to an unrelated default voice. For Montenegrin lessons, a Croatian voice may be used as an explicitly identified proxy when no Serbian voice is installed. The visible sound guide is generated from the same local spelling sent to TTS, so it cannot drift from a separately maintained phonetic field. Available voices, recognition quality, whether recognition is processed locally or by a platform service, and microphone permission behavior still depend on the browser and device.

Web Speech API reference:  
https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API

PWA installability reference:  
https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable

## Important prototype limitations

- The audio is generated by the device, not recorded by native speakers.
- Speech scores measure similarity to the device transcript; they are not professional pronunciation assessments.
- Progress is stored in the current browser only. The export button creates a JSON backup, but importing is not yet implemented.
- Role-play is structured and branching, not generative AI.
- Dialogue prices, schedules, travel times, and directions are teaching examples—not live travel information.
- Before commercial or public release, every translation, phonetic guide, and local-usage note should receive review by native Croatian and Montenegrin language professionals.

## QA completed

The automated browser smoke test checks:

- Every main route
- All 14 lessons
- Lesson tabs and quiz interaction
- Flashcard interaction
- Phrasebook search
- Quick phrase sheet
- PWA resource presence
- Desktop and mobile screenshots
- Runtime JavaScript errors

Run the static checks with:

```bash
node --check content.js
node --check app.js
```

The CDP smoke test in `tests/cdp_smoke_test.py` expects a Chromium remote-debugging instance and is included mainly as a reproducible QA record.
